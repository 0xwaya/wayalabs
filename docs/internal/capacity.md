# Capacity discipline

Internal. Phase 5 of the scale-up plan. Scale delivery hours without selling unfinished R&D.

## Concurrent builds

- Cap active platform + lead-system builds at **2–3**.
- Discovery sprints can run alongside builds (they are one week and produce a brief).
- When the cap is hit: lengthen the next build start date on the discovery call. Do not take a fourth custom build to “keep the pipeline warm.”

## When demand exceeds capacity

In order:

1. Confirm start dates later (honest queue).
2. Prefer lead-system over open-ended platform scope when both fit.
3. Raise the lead-system floor inside the published band for the next quotes (complexity must still justify it).
4. Add a contractor for frontend-only pages if needed — Wayalabs keeps architecture, data boundary, and handoff.

## Never

- Sell agent pilots or orchestrators to fill a slot
- Invent a new SKU because capacity is tight
- Skip discovery to jump straight into a build
- Drop Watch invites because “we’re busy”

## Agents

Echo, CEO orchestrator, and Grok operator sessions stay research / studio workflow. They compress delivery under human approval. They are not a product line until there is a reviewed demo, pricing, and support model — then update `offer-kit.md` first.
